Table Audit & Export for Confluence — documentation

Table Audit & Export reads every table on a Confluence page or blog post, checks the numbers and dates inside them, and exports the tables to a real Excel (.xlsx) file.

There is nothing to configure. The app has no settings page, no account, and no server-side component.

1. Installing the app

  1. In Confluence, open Apps → Explore more apps, or go to the app's listing on the Atlassian Marketplace.
  2. Search for Table Audit & Export and install it into your site. A Confluence administrator must approve the installation.
  3. The app asks for one permission: read:page:confluence (read access to page content). It cannot modify pages, and cannot reach spaces, users, attachments or any other Confluence data.

After installation there is no setup step. The app appears on every page and blog post for every user who can view them.

2. Running an audit, step by step

  1. Open any Confluence page or blog post that contains at least one table.
  2. Click the ••• (more actions) menu at the top right of the page.
  3. Choose Table Audit & Export.
  4. A full-screen dialog opens. It shows Opening…, then Reading this page…, then Checking the tables…. Large tables can take a few seconds.
  5. The results appear. Read them in the dialog, and/or click Download .xlsx to save the spreadsheet.
  6. Close the dialog when you are done. Nothing is saved to the page, and the page is not modified in any way.

You do not need to edit the page, select the table, or put a macro on it. The app reads the page as it is published.

3. Reading the results

The dialog opens with one summary line, for example “Found 3 tables on this page; 2 of them have problems worth fixing before the data is reused.” Each table then gets its own section.

Findings are grouped by column rather than listed cell by cell, so a 500-row table produces a report you can read in under a minute instead of a thousand separate lines.

Every finding states three things:

  • What is wrong — using the real values from your table, not a generic example.
  • Where — the column and the affected cell range.
  • Why it matters — what will go wrong if the data is reused as it is.

Each finding carries one of three labels:

LabelMeaning
Must fixThe table states something that is arithmetically wrong, or a value that will be read as the wrong thing by a spreadsheet.
Should fixThe data is usable but will cause trouble when sorted, summed or copied elsewhere.
Worth a lookWorth a human glance; often legitimate.

When the app cannot tell which of two readings is correct, it says so and shows you both. It will stay quiet rather than invent a problem.

4. What the app checks

On order, quote and invoice tables

  • Line total does not match — quantity × unit price does not equal the line total.
  • Total does not match — a total row does not equal the lines above it.
  • Tax does not match its rate — a tax line that disagrees with the rate the table itself states, for example 10% of 2,530,000 written as 250,000.

Subtotal, tax, discount and fee rows are checked against the stated total. Rounding is tolerated within the precision the table itself is written in, so a table rounded to the thousand is not reported for rounding.

On any table

  • Ambiguous dates — “04/02/2025” is 4 February in the UK and Vietnam, 2 April in the US.
  • Mixed date formats — a column that cannot be sorted as dates.
  • Mixed units — kg with lb with g in one column, which cannot be added up.
  • Ambiguous number separator — “1,410” means one thousand four hundred and ten in one spreadsheet locale and 1.41 in another.
  • Mixed currency marks — only some amounts in a column carry a currency sign.
  • Negative values — prices, quantities or weights below zero.
  • Empty cells — which totals and averages skip in silence.
  • Duplicate IDs — rows that cannot be looked up unambiguously.

Column headings are recognised in English, Vietnamese and German.

5. The exported spreadsheet

Clicking Download .xlsx builds the file in your browser and saves it through your browser's normal download. The file name is taken from the page title, for example Q3 plan - table audit.xlsx.

The workbook contains:

  • One sheet per table — the table's data, with dates written as real Excel dates and numbers as real numbers, ready to sort and sum.
  • An Issues sheet — one row per problem, giving the affected cell range and example values, plus an internal code in the last column.

A value that could be read more than one way is exported as text rather than being quietly converted into the wrong number. This is deliberate: a wrong conversion is harder to notice than a cell that stayed text.

There are no macros in the file.

6. Where your data goes

Nowhere. Everything runs inside your browser.

The page content is requested from Atlassian's own API and checked on your machine. There is no server of ours in the path, because there isn't one at all. There is no AI model in this app, no account to create, no analytics, no cookies, and nothing to opt out of.

7. Known limits

  • The app reads the tables on a single page or blog post at a time. It does not crawl a space.
  • Tables inside an expand are read; the report tells you when a table came from one.
  • The app reads the published page. Unsaved edits in the editor are not visible to it.
  • Values that could be read more than one way are exported as text rather than converted, on purpose (see section 5).
  • The app does not write to your page, and cannot fix anything for you. It reports; you decide.

8. Troubleshooting

“This page has no tables.”

The app checks tables in the page body. Open a page or blog post that contains a table. Note that a table pulled in by another macro at view time may not be part of the page body.

The dialog shows an error with a “Try again” button

Click Try again. If it keeps failing, reload the Confluence page first — a stale browser session is the most common cause.

“The file could not be created in this browser”

Nothing was downloaded. Try again, or open the page in another browser. The file is built in the browser, so a browser extension that blocks downloads or object URLs can prevent it.

The app is not in the ••• menu

Confirm with your Confluence administrator that the app is installed and enabled for your site. The app appears on pages and blog posts, not on other content types.

9. Reporting a problem

Email support@trunkle.win. We reply within two business days. Each screen in the app also carries a feedback link that opens a pre-addressed email.

Please include what you clicked and what happened, a screenshot of the app window if it showed an error, and roughly how many rows and columns the table has.

Please do not send us the contents of your table. We do not need it, and we would rather not receive it.
